# 样例与统计来源

这些文件来自2026年10月12日完成的J6E坐标还原实验，并保留原始数值。配套文章：[检测框画偏了？把 J6 模型输出的位置还原到原图](https://developer.horizon.auto/blog/14163)。

## 文件分别记录什么

- `../sample/transform.json`：案例 `COCO_val2014_000000181586_landscape_odd` 的尺寸、补边记录、数据哈希和已知矩形检查。
- `../sample/model_boxes.json`：该案例真实板端输出经量化解码、模型空间筛选/NMS后得到的一个框。
- `../sample/restored_boxes_reference.json`：按实际记录计算的原图坐标。
- `transforms/*.json`：28个构造视图的记录与输入一致性检查，共来自8张原照片。
- `summary.json`：28个视图上111个模型框、84个已知矩形的几何比较统计。

图片来自官方SDK示例集合，本仓库不重新分发原照片。模型输出数值、数据哈希和变换记录用于对应实验案例。

## 实验范围

环境：J6E MatrixB、OE 3.9.1、UCP 3.15.8、HBRT 4.11.11；模型是本轮固定KL校准YOLOv5s，模型输入画布672×672，运行时为NV12。

按记录实现的预处理与SDK参考生成的NV12，28组逐字节一致。首个案例还独立使用官方执行工具，三个有效raw与自有执行器一致。保存输出后，统一在模型坐标中筛选/NMS，再改变逆变换；不是28个视图共用同一份raw。

| 逆变换方式 | 111个实际框的最大坐标差，px | 每框最大坐标差均值，px |
|---|---:|---:|
| 按实际记录还原 | 0（比较基准） | 0 |
| SDK示例理想比例公式 | 1.242666 | 0.242004 |
| 故意漏减补边 | 248.244681 | 140.764623 |
| 故意按拉伸换算 | 107.084075 | 42.065698 |

差值以实际记录为基准，按每框四个坐标中最大的绝对差统计，裁剪前计算。两个大偏移值来自主动注入的错误，不是SDK的测量误差。84个已知矩形按记录正反变换的最大差为约5.7e-14像素，只验证算术对应。

这里没有真实目标标注的mAP结果，不能据坐标公式间的差值判断模型识别精度。完整板端raw和运行日志保留在原实验材料中，当前仓库提供数值样例与几何统计。

## 版本与整理记录

原板端图片处理依赖为NumPy 1.23.5、OpenCV 4.6.0；独立坐标样例于2026年10月12日在本地NumPy 2.4.4环境复核，与保存参考的最大差小于1e-10像素。坐标工具自身只依赖NumPy，不需要OpenCV、SDK或开发板。

2026年10月14日整理公开仓库时，直接复制原实验的坐标实现、命令行入口、已有检查用例和数值样例，静态核对源码哈希及JSON文件；没有重新运行模型或测试。`SHA256SUMS`记录公开版本中核心代码、样例与实验JSON的文件哈希。
